# Keyless Relay: the idea and the demo

ETHGlobal Tokyo 2026 · ENSv2 on Sepolia · working name "Keyless Relay" (rename before submitting)

## The idea in one paragraph

A company puts its API keys (OpenAI, Anthropic, Stripe, GitHub, …) into one relay, once. Everyone and
everything else gets an **ENS name** instead of a key. The name's records say which APIs it may use, how much
it may spend and until when. Access is handed down a tree of names (company → department → team → user →
agent → subagent), and nothing below can ever get more than what's above it. Remove a name and everything
under it stops on its next request. Nobody below the company ever holds a real key; they hold a name.

It works like LiteLLM's virtual keys, teams and budgets, except the rules live on ENS instead of in the
gateway's database. Anyone can read them, only the level above can change them, and every change is public.

## The tree (six layers)

```
acme.eth                                       company      · holds every API · set up once
└─ eng.acme.eth                                department   · set up once
   └─ dev.eng.acme.eth                         team         · set up once
      └─ derek.dev.eng.acme.eth                user         · created live in the demo
         └─ codex.derek.dev.eng.acme.eth       agent        · created by `relay codex`
            ├─ research.codex.derek…           subagent     · created by Codex itself
            └─ image.codex.derek…              subagent     · created by Codex itself
```

The first three layers are pre-generated by `npm run org:setup`, with three departments and six teams:

| Department | Teams | APIs the department may use (examples) |
|---|---|---|
| `eng` | `dev`, `platform` | OpenAI text (Codex), OpenAI Images, Anthropic, Gemini, GitHub, Railway, Vercel, Linear, Mock |
| `marketing` | `content`, `growth` | OpenAI text, OpenAI Images, Gemini, Canva, HubSpot, Mailchimp |
| `business` | `sales`, `finance` | Stripe, Notion, Slack, HubSpot, OpenAI text |

Only OpenAI (Codex and Images) uses a real key in the demo. The other APIs are in the catalog so the admin
portal can delegate them and the relay can enforce them, but they have placeholder keys or none. For the
pass-through APIs (everything except OpenAI, Anthropic, Gemini and Mock) the relay forwards any request except
the risky ones (new tokens, webhooks, access changes, revoking its own key), so scope real keys tightly.

## How it maps onto ENSv2

| Idea | ENSv2 feature |
|---|---|
| A person, team or agent | An ENS name. Its **owner** is the wallet that acts as it. |
| Creating names under a name | Each level gets its own **UserRegistry** (via the **Verifiable Factory**) hung under its name with `setSubregistry` |
| "Which APIs, how much" (the bundle) | **Text records** on a **Permissioned Resolver**: `relay.keys`, `relay.cap.<api>` (dollars), `relay.max.<api>` (count, e.g. 1 image), `relay.period` |
| Only the level above can change your limits | Your bundle lives on your **parent's** resolver, where you hold no roles (**Enhanced Access Control**) |
| A child can't widen what's above | The relay checks **every level's** bundle on every call |
| Agent sessions | The name's **expiry**. When it passes, the agent stops with no transaction. |
| Revoke | `unregister` on the parent's registry. Everything below becomes unreachable. |
| Fake or aliased subtrees | Rejected: every registry and resolver must pass `verifyContract` and `findCanonicalName` |
| Audit trail | ENS events: who created, changed or removed whom |

## What runs where

| Piece | Where | Holds |
|---|---|---|
| **Relay** (`/api/relay/<api>/…`) | Next.js server (`npm run dev`) | The real API keys, spend counters, the gas funder key |
| **Admin portal** (`/`) | Browser + MetaMask (the admin wallet) | Nothing secret; it signs ENS transactions |
| **CLI** (`./relay …`) | The user's laptop | The user's key and agent keys, in `~/.relay/` |
| **Codex** | The user's laptop, started by `./relay codex` | Only an access token for its ENS name |

On every call the relay:
1. checks the token was signed by the name's current owner
2. walks the name from the ENS root and checks every level is alive, allows the API, and has budget left
3. attaches the real key and forwards the call
4. adds the cost to every level

If a name is removed while a response is still streaming, the relay cuts it off within a few seconds.

## One-time setup (before any demo)

0. **Tools and gas:** `npm install`; install the Codex CLI (`npm i -g @openai/codex`); send about 0.05
   Sepolia ETH to the admin wallet and about 0.1 to the funder wallet. In the portal, **Connect wallet** (sidebar)
   opens a wallet picker; choose MetaMask (or the browser wallet holding the admin key) on Sepolia.
1. **Relay env** (`.env.local`):
   ```bash
   RELAY_ROOT_NAME=acme.eth            # your company name
   OPENAI_API_KEY=sk-...               # the one real key the demo uses
   FUNDER_PRIVATE_KEY=0x...            # small hot wallet with Sepolia ETH; tops up new users
   FUNDER_AMOUNT_ETH=0.02              # enough for login and two subagents even when gas is pricier
   NEXT_PUBLIC_SEPOLIA_RPC_URL=...     # your own RPC is strongly recommended
   RELAY_CODEX_MODEL=gpt-5             # a model your key can use that lib/relay/pricing.ts knows
   RELAY_IMAGE_MODEL=gpt-image-1       # needs a verified OpenAI org; otherwise dall-e-3
   ```
   Without `RELAY_CODEX_MODEL`, Codex uses its own default model, which the relay doesn't know. It is then
   billed at a $5/$20 per million tokens placeholder, and the $1 and $5 budgets run out fast (or set real prices
   in `RELAY_CODEX_PRICES`). Other API keys (`ANTHROPIC_API_KEY`, `STRIPE_SECRET_KEY`, `GITHUB_TOKEN`, …) are
   optional. Without them those APIs show as "no key" but can still be delegated.
2. **Build the org:** `ADMIN_PRIVATE_KEY=0x... ORG_LABEL=acme npm run org:setup`. This registers
   `acme.eth` (if needed) and creates the departments, the teams and their bundles. It is safe to re-run: it
   skips anything already done. It takes a few minutes on Sepolia. At the end it prints `RELAY_ROOT_NAME` and
   `RELAY_ROOT_OWNER` for `.env.local`.
3. Import the admin wallet into MetaMask for the portal.
4. `npm run dev` and open http://localhost:3000.

## The demo, step by step

**Before you start:**
- relay running (`npm run dev`), a terminal in this repo
- `ADMIN_PRIVATE_KEY=0x... npm run demo:reset -- --yes` (a clean tree, no old keys or files)
- portal open on **Access tree**, wallet connected as the admin on Sepolia; if `RELAY_ADMIN_TOKEN` is set,
  click **Sign in as admin** (otherwise the **Live view** under the tree says "The relay only shows spend and
  its log to the admin")
- let the tree load once in the portal: after a restart the relay's first read of the company tree can take
  up to a minute, and `./relay codex` would wait for it

1. **"I'm a new engineer."** In the terminal:
   ```bash
   ./relay init
   ```
   It prints a wallet address. Say: *this is my identity; I never get an API key.*

2. **"My admin adds me."** On the portal's **Access tree**, click the `dev` card (`dev.eng.acme.eth`), then
   **Add a member** (in its panel on the right, or the button at the top of the page once `dev` is selected):
   - ENS label `derek`, paste the address as **Owner wallet**
   - nothing is ticked yet: tick **OpenAI text (Codex)** with `$20`, **OpenAI Images** with `5` images,
     **GitHub** and **Linear**

   The editor only offers APIs the dev team itself is allowed; Stripe isn't available here, because nothing
   below can get more than what's above (type $500 for Codex and it says "Capped by dev.eng.acme.eth at $300").
   Click **Add derek.dev.eng.acme.eth** and confirm the two wallet prompts (register the name, then write its
   limits). The funder then tops up derek's wallet automatically. Click **Show derek**: derek is selected in the
   tree and the **Live view** under the tree switches to derek.

3. **"I log in to Codex with my ENS name."**
   ```bash
   ./relay codex
   ```
   This sends about 8 Sepolia transactions from derek's wallet (about a minute) and does five things:
   - finds `derek.dev.eng.acme.eth`
   - sets up derek's space for agents
   - creates `codex.derek.dev.eng.acme.eth` (Codex $5, 2 images, 8 hours)
   - installs the subagent skill in `demo-workspace/`
   - starts Codex pointed at the relay, with a token for its ENS name

   Codex never sees the OpenAI key.

4. **"Codex works, and spend moves."** Give Codex a task that needs research and an image, e.g.:
   > Research the three most popular ENS use cases this year and make a one-page brief with a header image.

   In the portal's **Live view** (under the tree), watch `codex.derek…` and its parents' spend go up. The
   selected name's panel and the "Estimated usage" figure at the top follow within a few seconds.

5. **"Codex creates its own subagents."** Following its skill, Codex runs:
   ```bash
   ./relay subagent create research --codex 1 --minutes 20
   ./relay subagent create image --images 1 --minutes 20
   ```
   Two new names appear in the portal under `codex.derek…` (in the Live view within seconds, in the tree
   shortly after), each with its own key and limits. Codex uses them:
   - `./relay exec --as research "…"`: the research subagent runs `codex exec` with its own $1 budget
   - `./relay image --as image --prompt "…" --out header.png`: exactly one image, and a second attempt is refused

6. **"I revoke it."** In the **Live view**, click **Remove derek.dev.eng.acme.eth**, then **Yes, remove it**
   and confirm in the wallet. Every name in derek's subtree turns *revoked* there, and derek's branch leaves
   the tree. (The same removal is in the tree: select derek, **Remove name & descendants**, then **Yes, remove
   it** in the "Remove access?" dialog.)
   - Any response still streaming is cut off within seconds.
   - Codex stops: its next call gets a 403 with *"access revoked: derek.dev.eng.acme.eth was removed or expired. Run ./relay login."*
     (`./relay` commands print the same line).
   - `./relay login` now fails, because derek has no name.
   - The subagents are dead too; nobody rotated a key.

## Resetting between demos

```bash
ADMIN_PRIVATE_KEY=0x... npm run demo:reset
```

This removes every user under the teams, clears the spend counters for removed names, deletes `~/.relay/`
and deletes what Codex made in `demo-workspace/` (e.g. `brief.md`, `header.png`; it asks first, add `-- --yes`
to skip the questions). It reads `RELAY_ROOT_NAME` and `RELAY_ADMIN_TOKEN` from `.env.local`; with the admin
token it also clears removed names from the relay's decision log. The company, departments, teams and the
launch squad stay. You can reuse the label `derek`: a re-registered name starts with fresh limits and no
leftover spend.

## Rehearsing the whole flow locally

```bash
npm run demo:e2e
```

This runs every step above on a local anvil fork of Sepolia, with the real relay (`next start` on port 3314), the
real `./relay` CLI and the real Codex CLI, and checks each result. OpenAI is a fake server, so it needs no Sepolia
ETH and no real key. It needs Foundry's `anvil` (or `ANVIL_BIN`) and takes about three minutes.

It doesn't touch the real OpenAI. Before the demo, check your key and models once on Sepolia (2 minutes), after
adding yourself in the portal:

```bash
./relay codex exec "say hi"
./relay subagent create image --images 1
./relay image --as image --prompt test --out /tmp/test.png
```

Then run `demo:reset` again.

## What's real and what's simplified

- **Real:** ENSv2 contracts on Sepolia, the tree, roles, records, revocation and expiry; OpenAI calls with
  your key; the relay's checks on every call.
- **Estimated:** Codex spend. Dollar amounts use estimated per-token prices (set `RELAY_CODEX_PRICES` for real
  ones). The demo only needs the numbers to move.
- **Placeholder:** every API except OpenAI.
- **Keys on the laptop:** `~/.relay/` holds real private keys (owner-only permissions). In the demo, Codex can
  read it so it can create subagents (it may write only `~/.relay/agents/` and `~/.relay/codex/`, not your own
  key). In production an agent should only hold its own key, and a small local helper would create subagents.
- **The relay holds the provider keys** and meters spend in `.data/relay.json`. In production it would run
  inside an enclave with a shared database.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `./relay codex` says "no name found" | The admin hasn't added your address yet, or you ran `init` again and got a new key |
| "insufficient funds" in the CLI | The funder is empty or unset; send Sepolia ETH to the funder address |
| Codex can't run `./relay` | Start it through `./relay codex`: it allows network access and write access to `~/.relay/agents/` and `~/.relay/codex/` |
| `./relay codex` prints "several names" | Your key holds more than one name the company added; pass `--name derek.dev.eng.acme.eth` |
| A subagent create fails with a nonce error | Run it again; the steps are idempotent |
| Spend doesn't move | Check the relay terminal; the portal's Live view (under the tree, and on the Agents page) refreshes every 3 seconds |
| Everything is slow | Set your own Sepolia RPC in `NEXT_PUBLIC_SEPOLIA_RPC_URL`; the public one is rate-limited |
